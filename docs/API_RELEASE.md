# ZeroWaste Listening Studio 0.13.1 · 느린 PC의 무응답 수집 대응

지식인·Reddit 수집이 일부 PC에서 오류 없이 오래 ‘수집 중’으로 남는 경로를 개선했습니다. 짧은 페이지 분석 대기가 끝나도 실제 분석은 계속 실행 중인데 새 분석을 반복 요청하던 구조와, 본문 이후 브라우저 저장소·세션 저장을 제한 없이 기다리던 경로를 수정했습니다.

- 페이지·프레임마다 실행 중인 분석 하나를 유지합니다. 1.5초보다 늦게 도착한 결과를 버리지 않고 받아 쓰며, 오래 응답하지 않는 분석은 명시적으로 종료합니다.
- 네이버 공개 수집 창은 본문을 확보한 뒤 저장소 정리 때문에 반환이 막히지 않습니다. 정리가 응답하지 않으면 다음 읽기에서 새 임시 공개 세션으로 복구하며, 반복 실패는 표시합니다.
- Reddit 쿠키 저장은 1.5초 한도를 두고 지연돼도 확보한 원문을 반환합니다. 렌더러 종료·무응답·페이지 연결 실패를 구분합니다. 로그인·보안 확인을 자동으로 누르거나 우회하지 않습니다.
- 네트워크가 취소 신호에 응답하지 않아도 제한 시간이 실제로 적용됩니다. 검색·본문·폴더 확인·파일 저장 대기를 구분하며, 이미 확보한 본문은 후속 응답 정체 시 보존합니다. 실제 사용자 확인 대기는 별도로 유지합니다.
- 화면 조회는 겹쳐 쌓이지 않으며, 원문은 레코드가 바뀐 경우에만 다시 전달합니다. 큰 번들에서 원문 전체를 1.2초마다 재전송·재분석하는 부담을 줄였습니다.
- 작업실의 ‘진행 상황’에서 검색어 번호·페이지·본문/댓글/파일 저장 단계와 대기 시간을 확인할 수 있습니다. ‘진단 복사’는 앱·OS·Electron 버전, 검색어·공개 URL, 단계·건수를 복사합니다. API 키·쿠키·원문·저장 경로는 포함하지 않으며 자동 전송하지 않습니다.
- 0.13.0의 네이버 최대 3건 병렬 수집·관련도순·중복 재사용·개별 MD/JSON과 두 메뉴의 미니멀 UI를 유지합니다.

## 검증 범위

단위 검사에 취소를 무시하는 작업·네트워크, 늦은 DOM 결과 재사용, 분석/댓글 동작의 중복 실행 방지, 지속 무응답 표시, 확보 본문 보존, 실제 보안 확인 대기 유지, 원문 변경분 조회와 진단 정보 제한을 추가했습니다. 화면 검사는 진행 단계·진단 복사와 느린 상태 요청이 겹치지 않는지 확인합니다.

네이티브 Electron 모의 페이지에서는 매번 2.2초 걸리는 지식인·Reddit 분석을 읽고 원문 전체·게시일·파일을 보존하는지 검사합니다. 종료되지 않는 네이버 저장소 정리를 주입해 새 공개 세션으로 이어가고, 종료되지 않는 Reddit 쿠키 저장을 주입해 원문을 반환하는지 확인합니다. 기존 네이버·Reddit 원문·댓글·페이지·CP949·세션·보안 확인 검사도 포함합니다.

보고된 특정 Windows PC·실제 번들에서 원인을 확정한 검증은 아닙니다. 문제가 재발하면 그 PC의 ‘진단 복사’ 결과로 현재 단계를 확인해야 합니다. Mac은 ad-hoc 서명이며 Developer ID 공증이 없습니다. Apple Silicon 패키지·소스·서명은 확인하지만 ARM64 실기기 실행은 미검증입니다.
