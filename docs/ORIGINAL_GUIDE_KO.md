# 0.12.0 설치·API 키 발급·원문과 댓글 저장 안내

이 앱은 네이버 블로그·카페·지식인과 Google에서 찾은 Reddit·Mumsnet·MoneySavingExpert 글의 공개 본문·댓글·답글을 한 파일에 이어서 저장합니다. AI 계정이나 AI 키는 필요 없습니다. 네이버는 기존 API 인증정보를 쓰고, 세 커뮤니티는 검색·수집용 API 키 없이 브라우저에서 읽습니다.

## 1. 설치 파일 받기

[공식 다운로드 페이지](https://github.com/sksmzldnl/research-crawler/releases/tag/studio-api-v0.12.0)에서 컴퓨터에 맞는 파일 하나를 받습니다.

- Windows 10/11 64비트: `ZeroWaste-Listening-Studio-0.12.0-win-x64.exe`
- Apple Silicon Mac(M1·M2·M3·M4·M5 등): `ZeroWaste-Listening-Studio-0.12.0-mac-arm64.dmg`
- Intel Mac: `ZeroWaste-Listening-Studio-0.12.0-mac-x64.dmg`

Windows는 파일을 실행해 설치 위치를 선택하고 설치합니다. 서명되지 않은 앱이므로 SmartScreen이 표시될 수 있습니다. 다운로드 주소와 파일명이 위 공식 배포본과 일치하는지 확인한 경우에만 ‘추가 정보 → 실행’을 선택하세요. 보안 기능을 끌 필요는 없습니다. Mac은 DMG를 열어 앱을 Applications로 옮깁니다. macOS 13 이상이며 ad-hoc 서명, Developer ID 공증은 없습니다. 실행이 차단되면 시스템 설정 → 개인정보 보호 및 보안에서 해당 앱의 허용 여부를 확인합니다.

업데이트할 때는 기존 앱을 종료하고 교체합니다. 앱의 기존 자료와 키 저장 위치는 유지됩니다.

## 2. 네이버 API 키란?

앱이 네이버 검색을 사용하도록 허용하는 인증정보입니다. 네이버 로그인 비밀번호와 다릅니다. **Client ID와 Client Secret 두 값**이 필요합니다. 다른 사람에게 보내거나 공개 문서에 붙이지 마세요.

## 3. 네이버 가입과 API 신청

1. [NAVER Cloud Platform](https://www.ncloud.com/)에 접속해 회원가입·로그인을 합니다.
2. 콘솔로 들어갑니다. ‘서비스 이용이 불가능한 계정’ 메시지가 나오면 화면의 계정 활성화·결제수단 등록 안내를 확인합니다. 결제수단 등록과 실제 사용요금 발생 여부는 별개입니다. 상품의 현재 요금·무료 조건은 공식 콘솔에서 확인하세요.
3. 콘솔의 Menu → All Services → Application Services → **NAVER API HUB**로 이동합니다. [Application 화면 바로가기](https://console.ncloud.com/naver-api-hub/application).
4. 처음 이용한다면 **Subscription → 서비스 이용 신청**에서 약관과 동의 내용을 확인하고 신청합니다.
5. **Application → Application 등록**을 누릅니다.
6. API 선택 단계에서 **NAVER 검색 → 블로그 / 카페 / 지식iN**를 선택합니다. 사용할 검색 종류를 모두 선택합니다. 기존 Application에는 지식iN을 추가하면 됩니다.
7. Application 정보에 이름을 입력합니다. 예: `zerowaste`. 영문·숫자·하이픈, 최대 20자 조건에 맞춰 등록을 완료합니다.
8. 만든 Application을 선택한 뒤 **인증 정보**를 누릅니다. Client ID와 Client Secret의 복사 버튼으로 각각 복사할 수 있습니다.

네이버 개발자 센터의 로그인 API, 클라우드 계정 로그인 비밀번호, 다른 상품의 Access Key는 이 앱의 검색 키가 아닙니다. 현재 이용 조건·과금·호출 한도는 [공식 안내](https://guide.ncloud-docs.com/docs/apihub-overview)를 확인하세요.

## 4. 앱에 키 입력

1. 앱을 열고 위쪽 **설정**을 누릅니다.
2. **네이버 Client ID** 칸에 복사한 Client ID 전체값을 붙여 넣고 옆의 **등록**을 누릅니다.
3. **네이버 Client Secret** 칸에 Client Secret 전체값을 붙여 넣고 **등록**을 누릅니다.
4. 두 칸 옆에 각각 ‘등록됨’이 보이면 저장된 상태입니다. 보안을 위해 값은 다시 표시하지 않습니다. 입력칸이 비워져도 정상입니다.
5. 요청 URL은 입력할 필요가 없습니다. 검색 요청 주소와 인증 방식은 앱이 처리합니다.

‘등록됨’은 키 저장 상태입니다. **연결 확인**을 누르면 검색 종류마다 검색 API·원문 읽기·게시일 결과가 표시됩니다. 검색 성공과 원문 성공은 별개입니다. 지식인만 403이면 Application의 지식iN 사용 권한을 확인하세요. 다른 PC에 설치하면 두 값을 다시 입력해야 합니다. 자기 계정 키는 제한이 허용하면 여러 PC에서 사용할 수 있지만 사용량·요금은 공유됩니다.

특정 카페 글이 실패하면 설정의 **원문 주소 확인**을 펼쳐 URL을 붙여 넣고 **원문 확인**을 누릅니다. 이 검사는 검색 API 키 없이도 해당 주소의 원문과 게시일을 직접 확인합니다. 진행 중에는 **중지**할 수 있습니다.

## 5. 처음에는 글 1개로 확인

1. 위쪽 **작업실**을 누릅니다.
2. 블로그·카페·지식인 중 하나를 선택합니다. 먼저 블로그를 권장합니다.
3. 기존 번들 ‘편집’을 누르고 원하는 검색 논리식을 입력합니다. 예: `텀블러 AND 후기`. ‘검색어 확인’으로 실제 검색어를 확인하고 ‘번들 저장’을 누릅니다. 사용할 번들의 체크박스가 선택되어 있어야 합니다.
4. 목표 자료 수를 `1`, 검색어당 페이지 수를 `1`로 설정합니다.
5. **파일 형식**을 Markdown(.md) 또는 JSON(.json)으로 고릅니다.
6. **폴더 선택**을 눌러 바탕화면이나 문서에 새 폴더를 만들거나 기존 폴더를 선택합니다. 이후 이 폴더에 파일이 만들어집니다.
7. **팝업·배너 광고 제거**는 기본으로 켜져 있습니다. 클릭하면 켜거나 끌 수 있습니다. 협찬 단어가 있다는 이유로 글 자체를 제외하지 않으며 광고 제거를 위해 NOT을 입력할 필요가 없습니다.
8. **해시태그 단어 제거**를 켜면 `#제로웨이스트`처럼 해시태그로 쓰인 단어를 본문에서 지웁니다. 기본은 꺼짐이며 일반 문장 속 같은 단어는 유지합니다. 제거 후 검색 조건을 적용하고 MD·JSON에 저장합니다. 이 선택은 새 수집에 적용되며 기존 파일을 바꾸지 않습니다.
9. **검색·수집 시작**을 누릅니다. 댓글도 기본으로 수집합니다. 네이버 검색 후 각각의 공개 원문과 댓글·답글을 읽어 자동 저장합니다.
10. 아래 ‘수집한 원문’에서 ‘저장 완료’를 확인하고 지정한 폴더를 엽니다. 파일이 1개 생성됐는지 확인합니다.
11. 제목을 클릭해 마지막 문단까지 수집됐는지, 게시일이 맞는지 확인합니다. 정상이라면 다음 수집부터 목표 수량을 늘립니다.

## 6. 파일에 들어가는 내용

MD는 제목·출처 URL·게시일·수집일·쿼리 번들 뒤에 본문 전체를 담습니다. 메모장, VS Code, Obsidian 등으로 열 수 있습니다. JSON의 `body`와 `body_markdown`에도 본문 뒤 댓글을 이어 붙입니다. `post_body`·`post_markdown`은 본문만, `comments`는 댓글 목록이며 `parentId`로 답글 관계를 보존합니다. `comments_status`는 `complete`(확인한 범위 완료), `partial`(일부), `unavailable`(확인 실패)입니다. JSON은 `title`, `url`, `published_at`, `published_at_confidence`, `collected_at`, `platform`, `query_bundle`, `body`, `body_markdown`, `content_status`를 담습니다. `body`는 본문·댓글 텍스트, `body_markdown`은 이미지·링크를 포함한 Markdown입니다.

성공한 글 10개를 조사하면 선택한 폴더에 파일 10개가 만들어집니다. 접근 실패나 검색 조건 제외 자료는 파일로 저장하지 않습니다. 기존 파일은 덮어쓰지 않으므로 같은 자료를 다시 저장하면 추가 파일이 생깁니다. 파일명은 제목과 구분용 ID로 구성됩니다.

이미지·첨부는 링크로 남기며 이미지 파일이나 동영상 자체는 다운로드하지 않습니다. 공개 댓글·답글은 원문 다음에 이어서 저장합니다. 댓글의 작성자·작성시각과 답글 관계를 보존합니다. 지식인은 질문과 현재 페이지에서 읽을 수 있는 공개 답변을 함께 포함합니다. 네이버는 로그인·카페 가입이 필요한 글을 읽지 않습니다. Reddit에서 로그인이나 확인이 필요하면 앱 브라우저에서 직접 처리하며, 계정 권한으로 볼 수 없는 자료와 삭제된 글·댓글은 복구하지 않습니다. 페이지가 로딩되지 않거나 지원하지 않는 구조면 실패로 표시하며 검색 요약을 원문으로 바꿔 저장하지 않습니다.

## 7. 기간·실패·재개·다시 저장

- **기간 설정**에서 시작일과 종료일을 지정합니다. 게시일이 없는 자료도 원하면 ‘게시일 미확인 자료 포함’을 켭니다. 미확인 자료는 해당 기간의 글임을 보장하지 못합니다. 앱은 날짜를 임의로 만들지 않습니다.
- 댓글 일부를 읽지 못해도 본문은 보존합니다. 목록·파일에 일부 수집 또는 확인 실패가 표시됩니다. **표시 → 댓글 확인 필요**로 모아서 볼 수 있고, 제목을 열어 **원문 다시 읽기**로 재시도합니다. 이전 버전 자료에도 이 방법으로 댓글을 추가할 수 있습니다.
- 글 하나의 댓글은 최대 5,000개이며 네이버는 최대 120초·읽기 동작 100회, Reddit도 댓글 읽기 동작 100회·120초로 제한합니다. 한도에 도달하면 일부 수집으로 남깁니다. 표시된 댓글 수에는 삭제·비공개 댓글이 포함될 수 있으므로 모두 복구할 수 있다는 뜻은 아닙니다.
- 게시일은 검색 API와 원문을 확인합니다. 확인된 글은 날짜를 표시하고, 원문에서 찾은 경우 상세 창에 ‘원문 확인’이 표시됩니다.
- 목표 수량은 ‘저장에 성공한 글’의 수입니다. 검색 결과·공개 범위·날짜·논리식·페이지 한도에 따라 부족할 수 있습니다.
- `The "MS949" encoding is not supported` 오류가 난 0.9.0 사용자는 0.12.0로 교체합니다. 키를 다시 발급하거나 카페에 로그인할 필요는 없습니다.
- 지식인 게시일이 미확인으로 저장된 기존 자료도 상세의 **원문 다시 읽기**로 다시 처리할 수 있습니다. 질문 작성일을 사용하며 답변 날짜나 수정일로 대신하지 않습니다.
- 이전에 실패한 자료의 제목을 열고 **원문 다시 읽기**를 누르면 새 추출기로 다시 읽고 저장합니다. 먼저 같은 저장 폴더를 선택해야 합니다. 날짜·검색 논리식·제외어는 다시 적용됩니다. 재저장은 기존 파일을 덮어쓰지 않습니다.
- ‘수집·저장 실패’를 선택하거나 ‘오류 보기’를 눌러 원인을 확인합니다. 네이버 401/403은 두 키와 블로그·카페 상품 신청을 확인하세요. 429는 호출 한도를 확인합니다.
- 원문 실패는 공개 여부·로그인·가입 필요 여부를 확인합니다. 저장 실패는 폴더 존재 여부, 쓰기 권한, 디스크 공간을 확인합니다.
- 수집을 일시정지하거나 중지하면 이미 저장된 파일은 유지됩니다. 재개하면 저장된 URL은 중복 저장하지 않습니다. 앱을 재실행했다면 먼저 ‘폴더 선택’으로 **기존 수집과 같은 폴더**를 다시 선택하고 해당 자료 모음의 ‘수집 재개’를 누릅니다.
- 다른 파일 형식이 필요하면 아래의 **다시 저장할 형식**을 고르고 **표시된 원문 N개 다시 저장**을 누른 뒤 폴더를 선택합니다. 전문 수집 성공 자료만 다시 저장할 수 있습니다.
- 앱에서 ‘기록 삭제’를 눌러도 폴더에 저장한 파일은 삭제되지 않습니다.

이전 버전의 검색 요약 자료는 그대로 보존되지만 전문이 필요하면 새 검색을 실행해야 합니다. 0.12.0에는 AI 요약·AI 키 설정·CSV 인사이트 기능이 없습니다.


## 8. Reddit 브라우저 준비

Reddit은 SerpApi 가입, Google 검색 API 키, Reddit API 앱 승인·키가 필요 없습니다. 네이버의 Client ID·Client Secret은 기존대로 사용합니다.

1. 설치한 앱의 **설정 → 커뮤니티 · Google 검색 → 수집 사이트: Reddit → 브라우저 열기**를 누릅니다. 별도의 앱 전용 브라우저 창이 열립니다.
2. 공개 글이 바로 보이면 로그인 없이 진행할 수 있습니다. 로그인이 필요하면 Reddit 사이트의 정상 로그인 화면에서 직접 진행합니다. 사용자 이름·비밀번호를 앱 설정이나 채팅에 넣지 않습니다.
3. 사이트가 2단계 인증·이메일·휴대폰·연령 확인을 요구하면 본인이 직접 완료합니다. 앱이 인증코드를 읽거나 대신 제출하지 않습니다.
4. 정상 로그인으로 생성된 유효한 세션은 이 컴퓨터의 앱 전용 브라우저 프로필에 유지됩니다. 다음 수집이나 정상 앱 재시작 때 사이트가 세션을 인정하면 다시 입력할 필요가 없습니다. 세션 만료·로그아웃·보안 정책 변경 시에는 다시 로그인해야 합니다.
5. **Reddit 연결 확인**을 누릅니다. Google 검색 화면에서 글 주소를 찾고 Reddit 원문·댓글·게시일을 읽는지 각각 확인합니다. 이때도 API 키는 사용하지 않습니다.

이전 버전의 SerpApi·Reddit API 키 입력칸은 제거했습니다. 이전 수집 파일과 기록은 보존됩니다. API 없는 Reddit 수집은 설치된 데스크톱 앱에서 사용합니다.

## 9. 로그인·보안 확인과 자동 재개

수집 중 확인 화면이 나오면 앱에 **브라우저 확인 필요**가 표시되고 브라우저 창을 앞으로 보여 줍니다.

1. 창이 보이지 않으면 앱의 **브라우저 보기**를 누릅니다. 현재 확인 중인 페이지를 그대로 보여 줍니다.
2. 해당 사이트에서 요구하는 로그인·동의·보안 확인을 본인이 직접 완료합니다. CAPTCHA나 보안 확인을 앱이 자동으로 풀거나 우회하지 않습니다.
3. 정상 검색 결과나 게시글 화면으로 돌아오면 앱이 이를 감지하고 **같은 작업을 자동으로 이어갑니다.** 진행 중에는 수집 재개 버튼을 따로 누를 필요가 없습니다.
4. 브라우저를 닫았거나 확인 대기 10분이 지나 일시정지됐다면 **브라우저 열기 → 필요한 확인 → 수집 재개** 순서로 진행합니다. 이미 저장한 글은 중복으로 만들지 않고 현재 검색 위치에서 이어갑니다.
5. 중단하려면 앱의 **일시정지·수집 중지** 또는 연결 확인의 **중지**를 누릅니다.

Google·Reddit이 해당 브라우저의 접속을 계속 차단하면 정상 수집을 보장할 수 없습니다. 차단 화면을 빈 검색 결과나 댓글 0개로 처리하지 않습니다. 앱은 브라우저 식별 위장, CAPTCHA 해결 서비스, 다른 브라우저의 비밀번호·쿠키 복사 기능을 사용하지 않습니다.

**세션 지우기**는 진행 중인 작업을 중지한 뒤 설정에서 누릅니다. 이 앱의 Google·Reddit 브라우저 로그인 상태와 저장 데이터를 지우므로 다음에는 다시 로그인해야 할 수 있습니다. 사이트 비밀번호를 앱이 별도로 저장하는 방식은 아닙니다.

## 10. Reddit 글 하나로 수집 확인

1. **작업실 → 검색 대상 → Reddit**을 선택합니다. 네이버 키가 없어도 이 대상은 사용할 수 있습니다.
2. **서브레딧 (선택)**에는 `ZeroWaste`처럼 커뮤니티 이름만 넣습니다. `r/`나 전체 URL은 붙이지 않습니다. 비우면 Reddit 전체를 검색합니다.
3. 번들에 영어 논리식을 입력합니다. 예: `reusable AND (cleaning OR complaint)`. 앱이 Reddit 사이트 또는 지정 커뮤니티 조건을 자동으로 붙여 Google 검색 화면을 엽니다.
4. 처음에는 목표 자료 수 `1`, 검색어당 페이지 수 `1`, 파일 형식 MD 또는 JSON을 고르고 **폴더 선택**을 누릅니다. 설정을 다녀와 폴더가 미선택이면 다시 지정합니다.
5. **검색·수집 시작**을 누릅니다. 검색 결과 페이지를 순회하고 게시글 ID로 중복을 제거합니다. Reddit 원문을 읽고 댓글 더 보기·답글 펼치기·같은 글의 계속 읽기 링크를 처리합니다.
6. 저장 파일에서 **원문 마지막 문단 다음에 댓글·답글이 이어지는지** 확인합니다. 글 하나당 파일 하나이며 본문과 댓글을 요약하지 않습니다. 이미지·동영상은 링크로 보존합니다.
7. 댓글의 일부만 읽었거나 총수를 확인하지 못하면 일부 수집·확인 실패가 표시됩니다. **표시 → 댓글 확인 필요**에서 모아 보고 **원문 다시 읽기**로 재시도할 수 있습니다. 이전 파일을 덮어쓰지 않습니다.

브라우저 로그인은 같은 컴퓨터의 유효한 세션을 재사용하는 방식입니다. 다른 PC에는 로그인 세션이 자동 전달되지 않습니다. 이 배포본은 격리된 페이지로 기능을 검증했으며 실제 Google·Reddit 계정·사이트 전체와 Apple Silicon 실기기 실행은 별도 확인이 필요합니다.


## 11. Mumsnet·MoneySavingExpert 수집

1. **작업실 → 검색 대상**에서 **Mumsnet** 또는 **MoneySavingExpert**를 선택합니다. 별도 API 키 입력은 없습니다.
2. 쿼리번들을 영어로 편집합니다. 예: `refill AND (cleaning OR expensive)`. 사용할 번들을 체크합니다. 앱이 선택한 사이트로 Google 검색 범위를 제한합니다.
3. 처음에는 목표 자료 수 `1`, 검색어당 페이지 수 `1`로 시작하고 MD 또는 JSON과 저장 폴더를 선택합니다.
4. **검색·수집 시작**을 누릅니다. 토론 원문을 읽은 뒤 댓글 펼치기와 다음 페이지를 처리하고 토론마다 파일 하나로 저장합니다. 다음 페이지의 반복 원글은 중복으로 넣지 않습니다.
5. 쿠키·로그인·보안 확인 화면이 나오면 **브라우저 보기**에서 직접 완료합니다. 완료하면 이어서 수집합니다. 사이트가 명시적으로 접근을 거부하면 실패 또는 일부 수집으로 표시합니다.
6. 원문 마지막 문단·게시일·댓글이 맞는지 파일을 확인합니다. 댓글 총수 미확인이나 시간·페이지 한도 때문에 일부만 읽었으면 **댓글 확인 필요**에 표시됩니다.
7. 연결 상태는 **설정 → 커뮤니티 · Google 검색 → 수집 사이트**에서 해당 사이트를 골라 **연결 확인**으로 점검합니다. 특정 글은 아래 **원문 주소 확인**에 URL을 붙여 검사합니다. 진행 중인 확인은 네이버 영역의 **중지** 버튼으로 중단할 수 있습니다.

브라우저 로그인 세션은 Reddit·Mumsnet·MoneySavingExpert가 각각 분리됩니다. 다른 PC에는 자동 전달되지 않습니다. **세션 지우기**는 선택한 커뮤니티와 그 전용 Google 브라우저의 데이터만 지웁니다.

영국식 `일/월/연도`, GMT/BST 작성시각을 지원하며 수정일·마지막 댓글 날짜를 원글 작성일로 사용하지 않습니다. 날짜만 있으면 시각을 임의로 채우지 않습니다. 댓글의 인용문은 인용으로 보존하고, 명시적 부모 정보가 없으면 답글 관계를 추정하지 않습니다.

글당 댓글 최대 5,000개, 댓글 페이지 최대 100페이지, 읽기 동작 최대 100회, 읽기 시간 최대 150초로 제한합니다. 사용자 확인 대기는 별도로 최대 10분입니다. Google에 색인되지 않은 글까지 전부 검색되는 것은 아닙니다.
