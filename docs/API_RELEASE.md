# ZeroWaste Listening Studio 0.13.0 · 네이버 수집 속도 개선

네이버 검색 결과를 한 글씩 원문·댓글까지 기다리던 방식을 개선했습니다. 검색 후보를 먼저 확인하고 최대 3건의 원문을 함께 읽으며, 목표 수량에 도달하면 남은 읽기를 중단합니다.

- 네이버 원문은 최대 3건씩 처리하고 저장은 순서대로 보호해 목표 수량 초과·파일 충돌을 막습니다. Reddit 브라우저는 기존처럼 한 작업씩 처리합니다.
- 같은 실행에서 동일 검색어·페이지의 API 응답을 재사용합니다. 실패한 중복 원문도 반복 요청하지 않으며, 재개할 때는 새로 시도합니다. 모바일·PC·추적·지식인 답변 URL 변형을 구분해 중복을 줄입니다.
- API 게시일이 기간 밖이거나 제목만으로 제외가 확정되는 자료는 원문 읽기 전에 제외합니다. 검색 요약에 긍정 검색어가 없다는 이유로는 제외하지 않습니다. 전체 본문·댓글에 대한 최종 번들 논리식은 유지합니다.
- 새 검색은 관련도순이 기본이며 ‘검색 조건·기간 → 검색 정렬’에서 최신순을 고를 수 있습니다. 이전 작업을 재개할 때는 기존 정렬·커서를 유지합니다.
- 변하지 않은 프레임 HTML을 매번 다시 분석하지 않습니다. 동시에 읽는 다른 창이 있는데 공개 세션 데이터를 지우지 않도록 정리를 조정했습니다.
- 댓글이 늘지 않는 대기는 줄이고, 확보한 본문·댓글과 미완료 사유를 저장합니다. 본문이 아예 없는 페이지의 브라우저 대기는 25초로 구분하고, 정적 읽기 전체는 20초 한도를 둡니다. 날짜·본문 지연 로딩과 정상 추가 댓글 읽기는 유지합니다.
- 재개 후 이전 오류를 현재 오류처럼 남기지 않습니다. 원문·댓글은 그대로 개별 MD/JSON으로 저장하고, 기존 미니멀 화면을 유지합니다.

## 검증 범위

단위 검사에서 동시 읽기 3건 제한, 느린 글이 있어도 먼저 준비된 유효 자료 저장, 목표 도달 시 남은 요청 취소, 목표 수량 준수, 중복 API·실패 원문 재사용, 재개 시 재시도, 안전한 사전 필터, 주소 구분과 Reddit 직렬 처리를 검증합니다. 동일한 모의 대기 9건의 순차 실행은 9초, 3건 병렬은 3초였습니다. 이는 실제 네이버 속도를 측정한 수치가 아닙니다.

로컬 Electron의 동적 모의 원문 3건은 동시 읽기 창 3개로 약 3.05초에 저장했고, 반복 생성되는 응답 없는 댓글 버튼은 약 9.17초에 확보 내용을 저장했습니다. 정상 지연 로딩, 페이지 댓글·답글, CP949, 지식인 게시일, 네이버 연결, 원문·댓글 파일 저장, Reddit 확인·세션 검사도 포함합니다. 실제 네이버 계정·검색 결과에서 유효 자료 증가율이나 속도 배수는 검증하지 않았습니다. 접근 제한·검색식·기간에 따라 실제 수량과 속도는 달라집니다.

Mac은 ad-hoc 서명이며 Developer ID 공증이 없습니다. Apple Silicon 패키지·소스·서명은 확인하지만 ARM64 실기기 실행은 미검증입니다.
