1. 설치 파일 받기

공식 다운로드 페이지에서 컴퓨터에 맞는 파일 하나를 받습니다.

  • Windows 10/11 64비트: ZeroWaste-Listening-Studio-0.10.0-win-x64.exe
  • Apple Silicon Mac(M1·M2·M3·M4·M5 등): ZeroWaste-Listening-Studio-0.10.0-mac-arm64.dmg
  • Intel Mac: ZeroWaste-Listening-Studio-0.10.0-mac-x64.dmg

Windows는 파일을 실행해 설치 위치를 선택하고 설치합니다. 서명되지 않은 앱이므로 SmartScreen이 표시될 수 있습니다. 다운로드 주소와 파일명이 위 공식 배포본과 일치하는지 확인한 경우에만 ‘추가 정보 → 실행’을 선택하세요. 보안 기능을 끌 필요는 없습니다. Mac은 DMG를 열어 앱을 Applications로 옮깁니다. macOS 13 이상이며 ad-hoc 서명, Developer ID 공증은 없습니다. 실행이 차단되면 시스템 설정 → 개인정보 보호 및 보안에서 해당 앱의 허용 여부를 확인합니다.

업데이트할 때는 기존 앱을 종료하고 교체합니다. 앱의 기존 자료와 키 저장 위치는 유지됩니다.

3. 네이버 가입과 API 신청

  1. NAVER Cloud Platform에 접속해 회원가입·로그인을 합니다.
  2. 콘솔로 들어갑니다. ‘서비스 이용이 불가능한 계정’ 메시지가 나오면 화면의 계정 활성화·결제수단 등록 안내를 확인합니다. 결제수단 등록과 실제 사용요금 발생 여부는 별개입니다. 상품의 현재 요금·무료 조건은 공식 콘솔에서 확인하세요.
  3. 콘솔의 Menu → All Services → Application Services → NAVER API HUB로 이동합니다. Application 화면 바로가기.
  4. 처음 이용한다면 Subscription → 서비스 이용 신청에서 약관과 동의 내용을 확인하고 신청합니다.
  5. Application → Application 등록을 누릅니다.
  6. API 선택 단계에서 NAVER 검색 → 블로그 / 카페 / 지식iN를 선택합니다. 사용할 검색 종류를 모두 선택합니다. 기존 Application에는 지식iN을 추가하면 됩니다.
  7. Application 정보에 이름을 입력합니다. 예: zerowaste. 영문·숫자·하이픈, 최대 20자 조건에 맞춰 등록을 완료합니다.
  8. 만든 Application을 선택한 뒤 인증 정보를 누릅니다. Client ID와 Client Secret의 복사 버튼으로 각각 복사할 수 있습니다.

네이버 개발자 센터의 로그인 API, 클라우드 계정 로그인 비밀번호, 다른 상품의 Access Key는 이 앱의 검색 키가 아닙니다. 현재 이용 조건·과금·호출 한도는 공식 안내를 확인하세요.

4. 앱에 키 입력

  1. 앱을 열고 위쪽 설정을 누릅니다.
  2. 네이버 Client ID 칸에 복사한 Client ID 전체값을 붙여 넣고 옆의 등록을 누릅니다.
  3. 네이버 Client Secret 칸에 Client Secret 전체값을 붙여 넣고 등록을 누릅니다.
  4. 두 칸 옆에 각각 ‘등록됨’이 보이면 저장된 상태입니다. 보안을 위해 값은 다시 표시하지 않습니다. 입력칸이 비워져도 정상입니다.
  5. 요청 URL은 입력할 필요가 없습니다. 검색 요청 주소와 인증 방식은 앱이 처리합니다.

‘등록됨’은 키 저장 상태입니다. 연결 확인을 누르면 검색 종류마다 검색 API·원문 읽기·게시일 결과가 표시됩니다. 검색 성공과 원문 성공은 별개입니다. 지식인만 403이면 Application의 지식iN 사용 권한을 확인하세요. 다른 PC에 설치하면 두 값을 다시 입력해야 합니다. 자기 계정 키는 제한이 허용하면 여러 PC에서 사용할 수 있지만 사용량·요금은 공유됩니다.

특정 카페 글이 실패하면 설정의 원문 주소 확인을 펼쳐 URL을 붙여 넣고 원문 확인을 누릅니다. 이 검사는 검색 API 키 없이도 해당 주소의 원문과 게시일을 직접 확인합니다. 진행 중에는 중지할 수 있습니다.

5. 처음에는 글 1개로 확인

  1. 위쪽 작업실을 누릅니다.
  2. 블로그·카페·지식인 중 하나를 선택합니다. 먼저 블로그를 권장합니다.
  3. 기존 번들 ‘편집’을 누르고 원하는 검색 논리식을 입력합니다. 예: 텀블러 AND 후기. ‘검색어 확인’으로 실제 검색어를 확인하고 ‘번들 저장’을 누릅니다. 사용할 번들의 체크박스가 선택되어 있어야 합니다.
  4. 목표 자료 수를 1, 검색어당 페이지 수를 1로 설정합니다.
  5. 파일 형식을 Markdown(.md) 또는 JSON(.json)으로 고릅니다.
  6. 폴더 선택을 눌러 바탕화면이나 문서에 새 폴더를 만들거나 기존 폴더를 선택합니다. 이후 이 폴더에 파일이 만들어집니다.
  7. 팝업·배너 광고 제거는 기본으로 켜져 있습니다. 클릭하면 켜거나 끌 수 있습니다. 협찬 단어가 있다는 이유로 글 자체를 제외하지 않으며 광고 제거를 위해 NOT을 입력할 필요가 없습니다.
  8. 해시태그 단어 제거를 켜면 #제로웨이스트처럼 해시태그로 쓰인 단어를 본문에서 지웁니다. 기본은 꺼짐이며 일반 문장 속 같은 단어는 유지합니다. 제거 후 검색 조건을 적용하고 MD·JSON에 저장합니다. 이 선택은 새 수집에 적용되며 기존 파일을 바꾸지 않습니다.
  9. 검색·수집 시작을 누릅니다. 댓글도 기본으로 수집합니다. 네이버 검색 후 각각의 공개 원문과 댓글·답글을 읽어 자동 저장합니다.
  10. 아래 ‘수집한 원문’에서 ‘저장 완료’를 확인하고 지정한 폴더를 엽니다. 파일이 1개 생성됐는지 확인합니다.
  11. 제목을 클릭해 마지막 문단까지 수집됐는지, 게시일이 맞는지 확인합니다. 정상이라면 다음 수집부터 목표 수량을 늘립니다.

6. 파일에 들어가는 내용

MD는 제목·출처 URL·게시일·수집일·쿼리 번들 뒤에 본문 전체를 담습니다. 메모장, VS Code, Obsidian 등으로 열 수 있습니다. JSON의 body와 body_markdown에도 본문 뒤 댓글을 이어 붙입니다. post_body·post_markdown은 본문만, comments는 댓글 목록이며 parentId로 답글 관계를 보존합니다. comments_status는 complete(확인한 범위 완료), partial(일부), unavailable(확인 실패)입니다. JSON은 title, url, published_at, published_at_confidence, collected_at, platform, query_bundle, body, body_markdown, content_status를 담습니다. body는 본문·댓글 텍스트, body_markdown은 이미지·링크를 포함한 Markdown입니다.

성공한 글 10개를 조사하면 선택한 폴더에 파일 10개가 만들어집니다. 접근 실패나 검색 조건 제외 자료는 파일로 저장하지 않습니다. 기존 파일은 덮어쓰지 않으므로 같은 자료를 다시 저장하면 추가 파일이 생깁니다. 파일명은 제목과 구분용 ID로 구성됩니다.

이미지·첨부는 링크로 남기며 이미지 파일이나 동영상 자체는 다운로드하지 않습니다. 공개 댓글·답글은 원문 다음에 이어서 저장합니다. 댓글의 작성자·작성시각과 답글 관계를 보존합니다. 지식인은 질문과 현재 페이지에서 읽을 수 있는 공개 답변을 함께 포함합니다. 로그인·카페 가입·권한이 필요한 글과 삭제 글은 수집할 수 없습니다. 페이지가 로딩되지 않거나 지원하지 않는 구조면 실패로 표시하며 검색 요약을 원문으로 바꿔 저장하지 않습니다.

7. 기간·실패·재개·다시 저장

  • 기간 설정에서 시작일과 종료일을 지정합니다. 게시일이 없는 자료도 원하면 ‘게시일 미확인 자료 포함’을 켭니다. 미확인 자료는 해당 기간의 글임을 보장하지 못합니다. 앱은 날짜를 임의로 만들지 않습니다.
  • 댓글 일부를 읽지 못해도 본문은 보존합니다. 목록·파일에 일부 수집 또는 확인 실패가 표시됩니다. 표시 → 댓글 확인 필요로 모아서 볼 수 있고, 제목을 열어 원문 다시 읽기로 재시도합니다. 이전 버전 자료에도 이 방법으로 댓글을 추가할 수 있습니다.
  • 글 하나의 댓글은 최대 5,000개이며 네이버는 최대 120초·읽기 동작 100회, Reddit 추가 댓글 요청은 최대 100회로 제한합니다. 한도에 도달하면 일부 수집으로 남깁니다. 표시된 댓글 수에는 삭제·비공개 댓글이 포함될 수 있으므로 모두 복구할 수 있다는 뜻은 아닙니다.
  • 게시일은 검색 API와 원문을 확인합니다. 확인된 글은 날짜를 표시하고, 원문에서 찾은 경우 상세 창에 ‘원문 확인’이 표시됩니다.
  • 목표 수량은 ‘저장에 성공한 글’의 수입니다. 검색 결과·공개 범위·날짜·논리식·페이지 한도에 따라 부족할 수 있습니다.
  • The "MS949" encoding is not supported 오류가 난 0.9.0 사용자는 0.10.0로 교체합니다. 키를 다시 발급하거나 카페에 로그인할 필요는 없습니다.
  • 지식인 게시일이 미확인으로 저장된 기존 자료도 상세의 원문 다시 읽기로 다시 처리할 수 있습니다. 질문 작성일을 사용하며 답변 날짜나 수정일로 대신하지 않습니다.
  • 이전에 실패한 자료의 제목을 열고 원문 다시 읽기를 누르면 새 추출기로 다시 읽고 저장합니다. 먼저 같은 저장 폴더를 선택해야 합니다. 날짜·검색 논리식·제외어는 다시 적용됩니다. 재저장은 기존 파일을 덮어쓰지 않습니다.
  • ‘수집·저장 실패’를 선택하거나 ‘오류 보기’를 눌러 원인을 확인합니다. 네이버 401/403은 두 키와 블로그·카페 상품 신청을 확인하세요. 429는 호출 한도를 확인합니다.
  • 원문 실패는 공개 여부·로그인·가입 필요 여부를 확인합니다. 저장 실패는 폴더 존재 여부, 쓰기 권한, 디스크 공간을 확인합니다.
  • 수집을 일시정지하거나 중지하면 이미 저장된 파일은 유지됩니다. 재개하면 저장된 URL은 중복 저장하지 않습니다. 앱을 재실행했다면 먼저 ‘폴더 선택’으로 기존 수집과 같은 폴더를 다시 선택하고 해당 자료 모음의 ‘수집 재개’를 누릅니다.
  • 다른 파일 형식이 필요하면 아래의 다시 저장할 형식을 고르고 표시된 원문 N개 다시 저장을 누른 뒤 폴더를 선택합니다. 전문 수집 성공 자료만 다시 저장할 수 있습니다.
  • 앱에서 ‘기록 삭제’를 눌러도 폴더에 저장한 파일은 삭제되지 않습니다.

이전 버전의 검색 요약 자료는 그대로 보존되지만 전문이 필요하면 새 검색을 실행해야 합니다. 0.10.0에는 AI 요약·AI 키 설정·CSV 인사이트 기능이 없습니다.

8. Google 검색용 SerpApi 키 받기

Reddit을 찾는 Google 검색에는 SerpApi라는 별도 서비스를 사용합니다. Google Cloud API 키나 네이버 키를 넣는 칸이 아닙니다. 네이버만 사용할 때는 이 절차가 필요 없습니다.

  1. SerpApi에 가입·로그인합니다.
  2. 대시보드의 API Key에서 본인 키를 확인합니다. API Key 전체값을 복사합니다. 키를 채팅·공개 문서에 붙이지 않습니다.
  3. 계정에서 현재 검색 제공량·요금·한도를 확인합니다. 이 안내는 무료 제공이나 특정 요금을 보장하지 않습니다. 한 번의 쿼리 번들이 여러 검색 조합·페이지를 만들면 요청 수도 늘어납니다.
  4. 앱의 설정 → Reddit · Google 검색 → SerpApi API 키에 붙여 넣고 등록을 누릅니다.

SerpApi는 검색 결과 주소를 찾습니다. Reddit 원문·댓글을 읽는 인증은 다음 절차로 별도 준비해야 합니다. 앱은 검색 결과의 발췌문을 원문으로 저장하지 않습니다.

9. Reddit 공식 API 승인·인증정보 준비

Reddit 원문·댓글은 Reddit 공식 API로 읽습니다. Google 검색 키만 등록해서는 원문을 수집할 수 없습니다.

  1. Reddit 계정을 준비합니다. 현재 Reddit Data API 안내에서 개발자 접근 신청과 이용 조건을 확인합니다. 신규 접근·용도에 따라 승인 절차가 필요할 수 있습니다. 단순 계정 가입이나 앱 생성이 API 접근 승인을 뜻하지 않습니다.
  2. 조사 목적, 수집 범위와 사용량, 보관·삭제 방식을 해당 신청 양식에 맞게 제출하고 승인된 범위를 확인합니다. 이 프로그램은 승인 제한을 우회하지 않습니다.
  3. Reddit 앱 관리에서 승인된 script 또는 web 앱의 인증정보를 확인합니다. 이 버전은 사용자 로그인 비밀번호를 받지 않고 앱의 읽기 전용 OAuth client_credentials 방식을 사용합니다. secret이 없는 installed 앱은 이 인증 방식에 맞지 않습니다.
  4. Client ID와 Client Secret 전체값을 각각 복사합니다. 앱 표시 이름·Reddit 사용자 이름·로그인 비밀번호는 이 두 값의 대체물이 아닙니다. Client ID가 앱 제목 아래 표시되거나 Secret이 별도 표시될 수 있습니다. 계정 화면이 다르거나 앱 발급이 제한되면 해당 화면의 승인 안내를 따릅니다.
  5. 앱의 설정 → Reddit · Google 검색에서 Reddit Client ID, Reddit Client Secret에 각각 입력하고 각 등록을 누릅니다.
  6. SerpApi 키까지 등록한 뒤 Reddit 연결 확인을 누릅니다. Google 검색 → Reddit 원문 → 댓글·게시일 결과를 확인합니다. 검색 성공만으로 Reddit 읽기 성공을 판단하지 않습니다.

401은 인증정보·앱 유형·토큰, 403은 해당 앱의 접근 승인·허용 용도, 429는 요청 한도를 먼저 확인합니다. 키를 새로 만드는 것만으로 승인 문제가 해결되지는 않습니다. 다른 PC에 배포할 때 앱에 공용 Secret을 넣어 배포하지 말고 허용된 인증정보를 해당 PC에 등록합니다. 앱의 현재 설정 화면은 두 값의 실제 내용 대신 등록 여부만 보여 줍니다.

10. Reddit 글 하나로 수집 확인

  1. 작업실 → 검색 대상 → Reddit을 선택합니다. 네이버 키가 없어도 Reddit용 세 값이 있으면 이 대상을 사용할 수 있습니다.
  2. 서브레딧 (선택)에 커뮤니티 이름만 입력할 수 있습니다. 예: ZeroWaste. r/나 전체 URL은 붙이지 않습니다. 비워 두면 Reddit 전체를 검색 대상으로 삼습니다.
  3. 번들을 편집합니다. 영어 글을 찾으려면 영어 논리식이 유용합니다. 예: reusable AND (cleaning OR complaint). 앱이 site:reddit.com 또는 지정 커뮤니티 조건을 자동으로 추가합니다.
  4. 목표 자료 수 1, 검색어당 페이지 수 1, 파일 형식 MD 또는 JSON을 고르고 폴더 선택을 누릅니다. 설정 메뉴를 다녀온 후 폴더가 미선택이면 다시 선택합니다.
  5. 검색·수집 시작을 누릅니다. Google이 찾은 글의 ID를 기준으로 중복을 제거하고 Reddit API에서 본문·댓글을 읽습니다. 댓글의 추가 로딩이 필요하면 순차적으로 요청합니다.
  6. 저장 파일을 열어 원문 마지막 문단 다음에 댓글·답글이 이어지는지 확인합니다. 글 하나당 파일 하나입니다. 이미지·외부 링크 게시물은 텍스트 본문이 비어 있을 수 있으며 제목·미디어 링크를 보존합니다. 이미지·동영상 자체는 다운로드하지 않습니다.
  7. ‘일부 수집’이면 해당 글을 열어 사유를 확인합니다. 삭제·접근 제한 댓글, 한도, 요청 실패 등을 모두 수집한 것으로 숨기지 않습니다. 실제 글의 댓글 수가 수집 도중 달라질 수도 있습니다.

Google에서 찾을 수 있는 글은 색인된 공개 글의 일부입니다. API 승인을 받았다고 해서 Google이 모든 Reddit 글을 찾아 주는 것은 아닙니다. 이 배포본은 격리된 응답으로 동작을 검증했으며 실제 계정·키·현재 사이트 구조 전체와 Apple Silicon 실기기 실행은 별도 확인이 필요합니다.
